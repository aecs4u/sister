## 0. Scope, constraints and honest caveats

- **Read-only on the portal side.** Only `GET` requests, theme/language toggles and **one failed login with a made-up user** (`audit.nonexistent@example.invalid`; it will show in the auth/access log). No query, batch, workflow, `/browser/*`, rescan, import, favourite or valuation write was sent. The SISTER/CIE session was never touched.
- **One extra in-process read:** to find the cause of A1 I imported the app in a throwaway Python process (`TestClient`, `GET /documents/1886`, no lifespan) from a script kept in the session scratchpad, not in the repo. It performed read queries only.
- **The service stopped answering at about 21:19** (finding S2) and did not come back during the session. I did **not** restart it (it is the user's terminal process). Everything below that needed a live server was done before that. **Not covered because of this:** a re-test of A1 after the template was touched at 21:19, the 3D page re-check, the mobile hamburger/sidebar drawer, Tabulator sort/filter interaction, the documents tabs filter latency, print/PDF, and the CSRF behaviour of write endpoints.
- **Contrast numbers** come from a script that resolves computed colours (including `oklch`) and alpha, and walks ancestors for the background. Elements on gradients/images are skipped, so hero banners and primary buttons are *not* in the counts. Third-party Swagger UI (`/docs`) is reported but not weighted.
- **Tap-target counts** treat 44 px as the target and 24 px (WCAG 2.2 AA 2.5.8) as the hard minimum; many are dense table links, so use the 24 px numbers for severity.
- I could not log in as another user, so role gating (`SISTER_ADMIN_USERS`) and cookie flags of a real session were not verified. Only the *anonymous* paths were.

## 2. Stability and errors

### 🔴 S1 — Sampled property-visura pages return 500 or reset
**Evidence.** Sampled ids from the `/documents` list: `1886, 1885, 379, 1146, 1757, 1876` → **500** `text/plain` "Internal Server Error" after 1.5–8.3 s; `143, 1549, 1846, 1883, 685, 100` → **`ECONNRESET` after 7–20 ms**; `1` → 500. Only `900` → 200. `GET /documents/1886/view` (the raw `.p7m`) → 200, so the file is fine. The log shows `Incoming request` with **no matching `Response:` line** and, before it, `Adjacent cadastral parcels unavailable: QueryCanceled`.
Reproduced in-process; the traceback ends in:

```
sister/templates/catasto/entity.html, line 246 (252 after the 21:19 edit)
    var completeSubjectReport = {{ (subject_fiscal_code|length > 0 or (doc and doc.query_only))|tojson }};
TypeError: object of type 'NoneType' has no len()
```

`subject_fiscal_code` is `None` for a property visura (it is only set for subject pages, `web.py` ~3623). The line belongs to the print/e-mail button block that was being added in the working tree.
**Impact.** The main reading surface of the app (open a stored visura) is unusable; users get an unstyled text error.
**Fix.** `(subject_fiscal_code or '')|length > 0`. Add a render test of `entity.html` with a property `doc` and no subject. Give 500s the same styled error page as the 404 (`SISTER - 404` already exists), plus a request id.
**Also:** the 1.5–8 s before the failure is the parcel-geometry query hitting its timeout; fail fast or load it asynchronously (see P2).
`[shot: none: error body only]`

### 🔴 S2 — Service wedged under `--reload` and did not recover
**Evidence.** Source files changed at 21:17:55 (`db_models.py`), 21:18:05 (`database.py`), 21:18:21 (`web.py`), 21:19:24 (`entity.html`) and a commit landed (`31c0e66`). The last log line is `Web UI inizializzata` at 21:19:51. From then: `ps` shows the reloader (`505375`) with a **zombie child `[python] <defunct>`** and no live worker; the main thread sleeps in `hrtimer_nanosleep`; the socket still **accepts** connections (Recv-Q 84–1592 bytes unread, several `CLOSE-WAIT`); `GET /health` timed out at 5, 6, 8 and 10 s for over 3 minutes. Postgres was healthy (1 connection, nothing active), importing `sister.main` in a separate process worked (`IMPORT OK`), so this is the reloader/worker lifecycle, not the app code.
I cannot prove my own traffic did not contribute (the last requests before the stall were sequential `/documents/<id>` and `/openapi.json`), but the timing matches the edits, not my requests.
**Fix.** For any instance that is audited, demoed or used for batch runs (`CLAUDE.md` already warns about reload) run without `--reload`, or under a supervisor that restarts a dead worker; add a Docker/systemd health probe on `/health` with a 2 s timeout so a stalled process is killed.

### 🟡 S3 — Silent degradations visible only in the log
`Manual property valuations unavailable: ProgrammingError` (every person/company render, so that section silently does not work although Alembic is at head `20261116_document_purchases`) and `Adjacent cadastral parcels unavailable: QueryCanceled`. Show an inline "dato non disponibile" note and count these in `/health`; today the UI looks complete.

### 🔵 S4 — Console noise on every authenticated page
`The resource /static/vendor/fonts/fonts.css was preloaded using link preload but not used within a few seconds` on ≈ 20 pages (theme `<link id="theme-fonts-link" rel=preload as=style>` is never applied as a stylesheet). Fix in `aecs4u-theme` (`onload="this.rel='stylesheet'"` or a real `<link rel=stylesheet>`).

## 3. Security, privacy and configuration

### 🟠 SEC1 — Plain-text local users are the live login source
`.env` line `# LOCAL_USERS_FILE=/git/aecs4u.it/sister/local_users.sister.txt` is **commented out** and its path is wrong. The restarted service logged `Loaded 5 local authentication users` and the plain-text warning. `../local_users.txt` is `-rw-rw-r--` (group/other readable); `../local_users.sister.txt` is `-rw-------` and hashed but unused. This contradicts the project notes ("`LOCAL_USERS_FILE` points at `local_users.sister.txt`").
**Fix.** Uncomment with the correct absolute path, delete or `chmod 600` the plain file, and make the service refuse to start with plain-text entries unless `ALLOW_PLAINTEXT_USERS=true`.

### 🟠 PRIV1 — Third-party data flows on person/company pages
- Server-side: `httpx GET https://nominatim.openstreetmap.org/search?q=VIA+ETTORE+PAIS+2,+PALERMO,...` is issued **during** `GET /persons/<cf>` (log 21:11:31; the page took 9.8 s). Home/property addresses of a person under inspection leave the machine on every uncached view.
- Browser-side: the map requests `server.arcgisonline.com/.../World_Imagery/MapServer/tile/...` (6 tile requests failed in this environment); `img-src` allows any `https:` host, so nothing would stop a future tracker.
**Fix.** Geocode only in the background and cache by address (and say so in the privacy page); self-host or proxy tiles, or at least put the Esri host in `img-src` explicitly and drop `https:`. Update the "no third-party requests" note in `CLAUDE.md` or make it true.

### 🟡 SEC2 — Public `/health` is chatty
Anonymous response includes auth mode (`cdp`), the human message ("Browser non avviato — usa il pannello…"), queue sizes, cache sizes and DB totals (`total_requests 4012, successful 2232, failed 1745, pending 35`). Return `{"status": …}` publicly and the detail only to an authenticated/API-key caller.

### 🟡 SEC3 — `HEAD /health` → 405
Load balancers and uptime tools often probe with `HEAD`. Accept `HEAD` (and `GET`) on `/health`.

### 🟡 SEC4 — Static file delivery
`/static/vendor/bootstrap-5.3.2/css/bootstrap.min.css` (233 KB) and `sister_actions.js` are served **without `Content-Encoding`** and with `Cache-Control: no-cache` (revalidate every navigation, ~40 requests per page). The path carries the version, so vendor files can be `public, max-age=31536000, immutable`; only SISTER's own assets need ETag revalidation. Add gzip/brotli for static types.

### 🔵 SEC5 — Smaller items
- CSP: `style-src 'unsafe-inline'`; the login page CSP additionally allows `cdn.jsdelivr.net`, Clerk and Google frames while the rest of the site does not (acceptable if Clerk login is used; otherwise drop).
- Login redirect uses `?next_url=%2Fresults`, while the form's hidden field is `next` and the page's own links use `?next=`. The 10-09 audit fixed this to `next`; it is `next_url` again. I could not complete a login to confirm the redirect target, so **verify** that the post-login redirect honours it.
- No `robots.txt`, `.well-known/security.txt`, web manifest or touch icon (all 404; harmless but noisy in logs). `Strict-Transport-Security` is sent over plain HTTP (ignored by browsers, harmless).

## 5. Functional UX

### 🟠 UX1 — Results table
`[shot: d1440_light_results, m375_light_results]`
- 18 Tabulator columns summing to 4,280 px (`Persona` 1,300 px, `Codice fiscale / P.IVA` 319, `Tipo richiesta` 386). At 1440 px the visible columns are `#`, `Rif. richiesta`, `Origine`, `Tipo richiesta`, `Categorie`; **`Stato` and `Data`, the two most useful columns, are the last two, off-screen.** At 375 px only `#` and a truncated id show.
- Row id `visura_storica_F_254…` is truncated to the point of being useless, and all 50 rows read "Singola / Visura storica per immobile / Consulta le variazioni…" (the same 14-word description repeated per row).
- Pager: `« Previous` is `<a href="#">`, "Page 1" with no total (4,012 rows = 81 pages), no first/last/page jump, no keyboard-reachable disabled state. Header says "Mostrate 1–50 di 4012".
- Filter placeholders are English ("e.g. Trie") and cut off at tablet width ("Codice fiscale o P.I…", "Cognome, nome o da…").
- `role="grid"` without an accessible name; header filter inputs have no label.
- TTFB 1.3–1.5 s for a page that renders 50 rows (the 4,012-row aggregation is recomputed per request).
**Fix.** Reorder: Data, Stato, Tipo, Soggetto/Immobile (one composed column), Provincia/Comune, Rif. (copy-on-click). Freeze the first two columns, keep ≤ 8 default columns with a column chooser, show a card list under 768 px, add numbered pagination, drop the repeated description into a tooltip.

### 🟠 UX3 — Query page: state, defaults and jargon

### 🟠 UX4 — Form validation and assistive text

## 6. Internationalisation and copy

### 🟠 I18N1 — Language switch
`?lang=en` on `/`: `<html lang>` becomes `en`; only *Profile / Notifications / Settings / Logout* change. The sidebar, headings, KPI labels, buttons and page body stay Italian. The choice is not stored: `/forms` immediately afterwards is `lang="it"` and `document.cookie` has no language entry. Either wire the Jinja translations to the `aecs4u-theme` locale catalog for SISTER's own templates, or remove the "English" option so the UI does not promise it.

### 🟠 I18N2 — English strings inside the Italian UI
`Profile` (title, h1) · `Logout` button · settings `User` · footer `API Documentation` · pager `« Previous / Page 1 / Next »` · results filter placeholders `e.g. Trieste` · form button `Clear` · result detail and dossier viewer `Results, Total Results, Error, All results, Documents, Copy, Toggle` · `No Match` badge · 404 `lang="en"` · `Sister workflow`. Italian-first is fine, but pick one language per surface.

### 🔵 I18N3 — Copy
`1 estratti` → `1 estratto`; `Mostrate 1–50 di 4012 risultati` → thousands separator `4.012`; dashboard `4012` and `3977` are unformatted while other pages use `€ 136.268`; "Fallite" for a state that includes "no match" (see UX5).
