## 0. Scope, constraints and caveats

- **Read-only.** Only `GET` requests, theme/sidebar `localStorage` toggles, and client-side search/filter/tab interaction. I did **not** click *Aggiorna*, *Importa nuovi*, *Reimporta tutti*, *Esporta con nomi*, *Importa output*, any favourite toggle, or *Filtra → CSV*; no query, batch or workflow was started and the SISTER/CIE session was never touched.
- **Environment friction (not a finding about the app).** The Playwright MCP profile was locked by a stale headless Chrome (pid 77594, from another `playwright-mcp` process). It was killed with the user's go-ahead. The profile had no session, so I signed in with the admin account from `../local_users.txt`; the password was read by a one-off script and never printed. The script was shredded afterwards.
- **Not covered:** print/PDF output of the three pages, `Esporta con nomi` / CSV downloads, the write endpoints (CSRF behaviour), Tabulator column drag/resize, the mobile hamburger drawer interaction, path-traversal on `/dossiers/<path>` **while signed in** (the anonymous probe returned 401 and the signed-in `/results/..%2f..` probe returned 404; the dossier handler was not hit with `..`), role gating (only the admin role was exercised), and 768 px dark.
- **Timings** come from one local machine with a shared dev server and a 4,012-request / 881-document database. Treat them as relative. Server load varied during the session (the same `/results?offset=999999` took 6 s via `fetch` and tripped a 30 s `networkidle` wait via navigation).
- **Contrast** skips elements on gradients/images. Tap targets: 24 px (WCAG 2.2 AA 2.5.8) is the hard line, 44 px the target.
- Counts: DB had 4,012 requests (2,232 completed · 0 partial · 652 failed · 35 pending · 1,093 no-match), 881 indexed documents (1,068 files), 13 dossier JSON files.

## 3. `/results`

### R1 🟠 Key columns off-screen, identity column often empty
[shot: `d1440_light_results_full`]
- Tabulator holder: `scrollWidth 2517` vs `clientWidth 1342`. Column widths: Data 184, Stato 170, Tipo richiesta 209, **Soggetto / immobile 1,292**, Comune / provincia 287, Rif. richiesta 255, Origine 120. Only the first four are visible without horizontal scrolling and the first two are frozen.
- Hidden by default (width 0): *Categorie*, ***Codice fiscale / P.IVA***, *Provincia*, *Comune*. Also hidden: *Catasto*, *Foglio*, *Particella*, *Immobili registrati*, *Intestatari registrati*, *Conteggi estratti*. The page offers a form that filters by provincia/comune/CF/foglio/particella, but the table cannot show those fields unless the user finds *Scegli colonne*.
- In the first 9 rows, 4 of the *Soggetto / immobile* cells are just `—` (including completed requests and every no-match), so the row does not say what was searched. The place (comune) is in an off-screen column.
- **Suggestion:** cap the Soggetto column (e.g. 320–420 px, `text-truncate` + tooltip/expand), move *Comune/provincia* before it, show CF by default, and drop *Rif. richiesta* (it is the detail link; a short ID column or an icon is enough).

### R2 🟡 Table chrome and states
- The 600 px-high table scrolls inside the page (holder 2,940 px tall), a second vertical scroll region next to the page scroll. With 50 rows/page and a pager below, that nesting is avoidable.
- *Nessuna corrispondenza* badge is clipped by the next column ("Nessuna corrispondenza" cut at the frozen-column edge) [shot: `d1440_light_results`].
- Header filters mix text inputs pre-filled with **"Tutti" / "Tutte"** (look like values, not "no filter") with a separate form above that filters server-side. Two filter systems, one page: header filters act on the 50 loaded rows, the form on all 4,012, and the UI does not say so (compare the explicit hint on `/documents`).
- Row has `cursor: pointer` (whole-row click) but rows are not focusable (`tabindex` null); the only keyboard route is the ID link, which is in an off-screen column and truncated to `visura_storica_F_254…`.
- Placeholders `9` and `166` in *Foglio* / *Particella* read as data; use "es. 9" like the others.
- Pager: "Pagina 1 di 81" with First/Prev/Next/Last; no jump-to-page for 81 pages.
- 10 controls at 16×16 px at ≥ 768 px (below the 24 px minimum).

### R3 🟡 Console warnings on every load
`Find Error - No matching column found:` for `request_type_tags`, `tipo_catasto`, `provincia`, `comune`, `foglio`, `particella` (6 warnings per load, all four viewports/themes). The script applies header-filter or visibility settings to columns that do not exist as filterable columns. Harmless today, but it means the form values for *Provincia/Comune/Foglio/Particella* are not reflected in the table header filters.

### R4 🟠 Status mismatch list ↔ detail
`/results?status=no_match` → "Nessuna corrispondenza" (grey badge). Detail `/results/visura_storica_F_2541da87a1db449d889c2c59c5c1c5c4` shows red **"Fallita"**, with an alert "NESSUNA CORRISPONDENZA TROVATA" in capitals, "Total Results 0" and a section titled "Error" [shot: `m375_light_detail_results_visura_storica_F_2541…_full`]. `no_match` is a valid answer from SISTER (CLAUDE.md: final, not an error); the detail page should use the same status vocabulary and tone.

### R5 🟠 Detail of a pending / failed request claims results
`/results/visura_storica_F_d47a0c2e…` (*In attesa*): header "Risposta estratta – Dati normalizzati restituiti dalla richiesta eseguita", chips "0 risultati" / "0 intestatari", although "La richiesta esiste, ma non è ancora stata salvata una risposta". Hide the chips and rename the card when there is no answer. [shot: `d1440_light_detail_results_visura_storica_F_d47a…`]

### R6 🟡 Query-string robustness
| URL | Observed | Expected |
|---|---|---|
| `?limit=abc` | **422 JSON** (`{"detail":[{"type":"int_parsing",…}]}`) on an HTML page | Ignore or redirect with default |
| `?limit=100000` | silently clamped to 200 (an offered value of the *Righe* dropdown) | ✅ |
| `?status=bogus` | silently ignored, dropdown shows "Tutti gli stati" | OK, but no notice |
| `?offset=-5` | treated as 0 | OK |
| `?offset=999999` / `?offset=4012` | 200, 50 KB page, 6.0–6.3 s, empty state "Nessuna richiesta eseguita · Nessuna richiesta corrisponde ai filtri selezionati" + CTA "Invia una query"; no filters were applied and 4,012 requests exist | clamp to the last page, or say "Pagina oltre la fine" with a link to page 1 [shot: `d1440_light_results_offset_oob`] |
| `?offset=4000` | "Mostrate 4.001–4.012 di 4.012" | ✅ |
| `?q=<script>alert(1)</script>` | unknown param ignored, nothing reflected | ✅ |
| `/results/does_not_exist` | 404, "Richiesta con ID does_not_exist non trovata." | ✅ |
| `/results/..%2f..%2fetc%2fpasswd` | 404 "Pagina non trovata" | ✅ |
`web_results` (`sister/web.py`) took `limit: int = 50, offset: int = 0`, which is what produced the 422.

### R7 🟡 Performance
- TTFB 1.1–1.4 s for the unfiltered list at every viewport; filtered/paged views 2.2–3.2 s wall-clock, `?offset=999999` 6 s. The aggregation behind the six stat cards and the owner/property counts is the likely cost; cache the stats or compute them with one `GROUP BY`.
- 4,703 DOM nodes on desktop vs 2,103 on mobile suggests both the Tabulator table and a card list exist in the desktop DOM, or Tabulator's virtual DOM is larger than needed for 50 rows; worth checking.
- Mobile: 50 cards × ≈ 590 px = **29,586 px** of scrolling for one page.

### R8 🟡 Mobile list (375 px) [shot: `m375_light_results`]
- The page switches from table to cards; each card has an `<h2>` "Visura storica per immobile" (50 identical headings, 53 in total) which makes the heading outline unusable. Use the subject/property as the card title and the request type as a badge, as the desktop table does.
- "Senza corrispondenza" stat card: the `?` icon overlaps the label.
- The six stat cards take ≈ 3 screens before the first filter/result.

### R9 🔵 Naming and navigation
Sidebar "Risultati", `<title>` "SISTER - Risultati", H1 "Richieste eseguite", detail breadcrumb "Risultati", related link "Tutti i risultati". Pick one noun. `/results` is the only one of the three pages without a breadcrumb.

### R10 🟡 Result detail pages (`/results/<id>`)
[shot: `d1440_light_detail_results_visura_storica_T_1718…_full`]
- **No `<h1>`** (the first heading is `h5` "Risposta estratta", then `h4`); the document title is "Risultato visura_storica_T_171…".
- Section titles are raw JSON keys, in English: *Results*, *Results · Intestati*, *Total Results*, *Skipped Soppresso*, *Error*, *Immobili (1) DB*. Tabulator's pager is English (*Page Size*, *First*, *Prev*, *Next*, *Last*), filter inputs say "Filtra…".
- *Accessi alle pagine* prints raw portal paths as link text (`/Visure/DataRichiesta.do`, 4.36:1 contrast, below 4.5) and timestamps with microseconds (`2026-10-29T20:54:31.389098`). For a human reader this is a debug log; collapse it by default.
- The same data is shown three times (*Immobili*, *Results*, *Immobili … DB*; *Results · Intestati*, *Intestati*, *Intestati … DB*) on the sampled completed result: 8 tables for one parcel and one owner.
- 4 unlabeled inputs per page (Tabulator header filters; placeholder only); the *Raggruppa* / *Cumula identici* switches are 32×18 px.

### R11 🟡 Mobile overflow on result detail
At 375 px the page is 390 px wide on `/results/visura_storica_T_1718…`, `…F_2541…` and `soggetto_E_1a65…`; the offender is the *JSON originale* header row (`div.d-flex.gap-2` with *Copia* and *Mostra/nascondi*) [shot: `m375_light_detail_results_visura_storica_F_2541…_full`]. Add `flex-wrap`.

### R12 🔵 Pending/failed pages are mostly empty
Pending and failed detail pages are 1,173–1,220 px tall: header, two chips, one alert, related links. No next step ("Riprova", "Apri la query originale") is offered.

### R13 🔵 Dates
`/results` list uses `2026-10-29 20:54` + "Risp. 2026-10-29 20:55" (ISO-like); detail uses `2026-10-29 20:54`; the page-log table uses microsecond ISO; `/documents` uses `29/10/2026` and `2026-10-29 20:31` in the same row (DOC6). Choose one display format (`display.py` already has the filters).

## 4. `/dossiers`

[shot: `d1440_light_dossiers`, `m375_light_dossiers`]

## 5. `/documents`

### DOC1 🟠 Counts and scope are inconsistent
[shots: `d1440_light_documents`, `…_documents_view_map`, `…_documents_view_files`]
- Header: "881 documenti indicizzati · 1068 file". Pager: "Mostrati 1–100 di 881 … Filtri e ordinamento riguardano la pagina corrente."
- All three tab badges say **881**, yet *Per file* shows "100 documenti" + "119 file indicizzati".
- *Per categoria*: Visura per Immobile **80**, per Soggetto **17**, Elenco 1, Planimetria 2 (= 100). *Per ubicazione*: Immobili **86**, Soggetti **9**, Altri 4 (= 99). The same 100 documents land in different buckets, and the totals are 99 vs 100.
- Four separate "Filtra…" boxes (one per category table), all with the same placeholder and `aria-label`, filter only what is on this page. A user searching for a codice fiscale among 881 documents will get "no results" for 8 of 9 pages.
- **Suggestion:** server-side search (one box, applied to all 881), badges that show the filtered total and are consistent per tab, and the "pagina corrente" sentence only if client filtering stays.

### DOC2 🟠 ARIA tabs that navigate
`#documents-tab-categories|location|files` carry `role="tab"`, `aria-selected`, `aria-controls="documents-pane-…"`, `tabindex` roving (0 / -1 / -1). Clicking *Per ubicazione* loads `/documents?view=map`; *Per file* loads `?view=files`. Either make them links (`<nav>` + `aria-current="page"`) or make them real in-page tabs (all three panes in the DOM).  The tab labelled "Per ubicazione" has the URL `view=map` while *Mappa catastale* is `view=cadastral-map` (naming collision).

### DOC3 🟡 Layout of the first screen
At 1440 × 900 the first screen holds: 8 toolbar buttons on two rows, a lone right-aligned *Solo preferiti*, the pager, the tab row, and the "Tipi di documento supportati" reference card (≈ 280 px, three columns of text). The first actual table starts below the fold (y ≈ 830). Collapse the reference card by default (it already has *Espandi/Riduci*), and put *Solo preferiti* with the filter row.
- Pager appears twice (top and bottom) with disabled "Prima/Precedente" styled differently from the active "Successiva/Ultima" (grey filled vs. white). OK, but on the *Per file* tab a user has to scroll up for it.

### DOC4 🟡 Toolbar semantics and safety
| Button | Behaviour |
|---|---|
| Aggiorna | `POST /documents/rescan` (form, no confirmation) |
| Importa nuovi | `importDocuments(false)` ("Indicizza i file nuovi e riempie le tabelle strutturate…") |
| Reimporta tutti | `importDocuments(true)` ("Rielabora tutti i documenti XML già importati"). **Correction:** it does ask for confirmation (`window.confirm` in the page script; I only looked for a `data-confirm` attribute and missed it). It still sat in the same row as the harmless buttons, styled like a secondary action |
| Esporta con nomi | `exportNamed` |
- *Aggiorna* vs *Importa nuovi* are hard to tell apart. Group them under one "Aggiorna archivio" menu (rescan / import new / reimport all); the last one already confirms.
- Six visual variants in one toolbar (neutral, warning, info, success, grey, plus the red *Solo preferiti*): colour carries no consistent meaning.

### DOC5 🟡 Targets and contrast
- **100 favourite buttons 24×30 px** (the hit area is the heart only). Pad to ≥ 32 px; they are the most repeated control on the page.
- Light: 5 failures — the `badge text-bg-secondary` counters (**4.47:1**, 12 px) and *Reimporta tutti* label (4.49:1). Dark: 4 (the same badges). Near-misses, trivially fixed by using a darker secondary.

### DOC6 🔵 Table content
First table: 11 columns, 1,501 px wide in a 1,299 px container (inner horizontal scroll); *Per file* clips the action column (heart + eye) at the card edge [shot: `…_view_files`]. Same-row dates: *Data riferimento* `29/10/2026`, *Data* `2026-10-29 20:31`. No `<caption>` and no `aria-sort` interaction (all `none`), so the column headers look sortable by the page text ("ordinamento…") but the probe found no active sort state.

### DOC7 🔵 Location view
*Per ubicazione* is the nicest part: Provincia → fogli → docs with counts, *Espandi tutto / Comprimi tutto*. The group header colour (dark grey on dark grey in light theme, white text 8:1) is heavier than it needs to be.

## 6. Cross-cutting

### A1 🟠 Hidden sidebar is still focusable
`.sidebar-hidden .sidebar { transform: translateX(-100%) }` (`aecs4u-theme/…/css/layout.css:298`) and `restoreSidebarToggleState` (`theme.js`) only toggle a class. In the hidden state the sidebar has `visibility: visible`, no `inert`, no `aria-hidden`: its first link sits at x = −264 px. On all three pages Tab stops 6–22 are the sidebar links (*Panoramica … Documentazione API*), invisible. Add `visibility: hidden` (with a transition delay) or `inert` when hidden. The skip link "Vai al contenuto principale" → `#main-content` works and is the first stop. ✅

### A2 🔵 Layout shift on load
The server renders `sidebar-visible` and JS then restores the saved `sidebarHidden` state; I caught the intermediate frame once (sidebar sliver and content shifted 45 px at the left) when `localStorage.sidebarHidden = "true"` on a 1440 px window [shot: `d1440_light_results_offset_oob`]. Set the class in an inline `<head>` script (nonce already available) before first paint.

### A3 🔵 Mixed security/privacy statements
The CSP seen on `/auth/login` allows `script-src … https://cdn.jsdelivr.net` and Clerk origins while CLAUDE.md says all libraries are self-hosted and `connect-src`/`script-src` are `'self'`; `style-src` has `'unsafe-inline'`. If nothing uses jsDelivr, drop it. HSTS, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy` are present ✅.

### A4 ✅ Access control
Anonymous `GET` of `/documents`, `/dossiers`, `/results`, `/dossiers/view/…`, `/results/<id>`, `/documents/<id>` → **401** (fail closed). `/health` is public. Page responses for the signed-in admin carry no `Cache-Control` issues observed (not tested in depth).

## 7. Design review notes

**Consistent and working:** page headers with an icon, a breadcrumb (two of three), subtitle and right-aligned actions; the card + badge language; group colours for query types (green = immobile, teal = soggetto, blue = intestatari, amber = batch) used consistently between `/dossiers` chips and `/documents`; the "Collegamenti correlati" footer on every page; empty/404 states with a next action; 1440 → 375 layouts do not overflow on the three list pages.

**Inconsistent:**
- Three different "table" implementations: server-rendered tables with inline filters (`/documents`), Tabulator (`/results`, result detail), cards with client-side filtering (`/dossiers`). Each has its own filter box, pager and empty state wording.
- Three different density levels on the same page-header pattern (the `/results` header has no breadcrumb and a plain text counter on the right; the others have action buttons).
- Colour as meaning: green button = export on `/documents`, green card = OK on `/dossiers`, green badge = "Completata" on `/results`; yellow = rescan / errors / batch.
- Vocabulary: *Risultati / Richieste eseguite / Risultato*, *Dossier / Risposta estratta / Risultato*, *documento / file / allegato*.

**Mobile:** `/documents` and `/dossiers` stack toolbars full-width (good); `/results` becomes 590 px cards (long); detail pages overflow slightly (R11).
